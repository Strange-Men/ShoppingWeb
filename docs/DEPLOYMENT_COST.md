## 地域选择

用户覆盖欧美、中亚、印度和港澳台，目前没有各地区流量占比。暂将新加坡作为起步候选，便于在较低费用下启动；这不是已经证明的最优网络线路。欧美占比高时可比较法兰克福／美国地域，香港客户占比高时可比较香港；购买前结合目标国家访问测试与可售资源决定。

先单机静态站，不同时买多地域服务器。上线后如目标地区实测慢或图片流量增加，再评估海外 CDN／腾讯云全球加速产品的实际报价与收益。不要把“外国人可访问”与“各地延迟一致”混为一谈。

## 域名与备案

腾讯云说明中国香港及境外地域服务器无需中国大陆 ICP 备案：[官方文档](https://cloud.tencent.cn/document/product/243/18908)。若未来改用大陆服务器或大陆加速节点，重新确认对应接入和备案要求。域名注册实名／账号验证与 ICP 备案是不同步骤，按注册商当时要求完成。

正式解析优先配置 A 记录到已分配公网 IPv4；仅在已验证 IPv6 连通时配置 AAAA，避免发布不可达地址。选择主域名后配置 www 与裸域之间单向跳转；DNS TTL、证书 SAN 和 Search Console 验证值按实际资源填入。

## 发布规划

1. 在本地／构建环境锁定 Node 与依赖，运行类型、内容、链接和构建检查，产出 dist；不得在生产填入调研原始响应。
2. 选定腾讯云地域、系统和套餐；配置 SSH 密钥、安全组及最小必要管理入口，开放 HTTP／HTTPS。
3. 安装 Nginx；静态版本按 `/var/www/sculpture/releases/{releaseId}/` 存储，current 指向已验证版本。
4. 配置域名、证书、自动续期验证、HTTP 至 HTTPS 和根路径至 `/en/` 重定向；正式 noindex 切换单独检查。
5. Nginx 以实际文件／目录解析页面，类似 try_files $uri $uri/ =404，错误路径不回落首页；404 页面需保持真实 404 状态。依据 [Nginx 官方文档](https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files)。此处为设计示意，不是可直接复制的完整生产配置。
6. 内容指纹资源长缓存，HTML 使用短缓存或需重验证策略；字体与图片尽量同域；启用合适压缩和日志轮转。
7. 从目标区域检查 DNS、TLS、HTML、图片、页面刷新与咨询跳转，记录网络探测来源和结果，不用本机一次访问代替海外检查。
8. 验证通过后切换 current；留存上一版本，发现问题切回并复测。Search Console 提交与索引状态另行记录。

自动化上线不是第一阶段必需项。后续如使用 GitHub Actions，部署凭据存平台密钥配置，未完成之前不得声称已经存在 CI/CD。服务器续费、域名续费、证书到期和流量告警需交接给业主。

## 海外探测矩阵

至少覆盖美国、一个欧洲国家、印度、一个实际业务相关的中亚国家、香港与台湾；澳门尽可能补测。具体中亚国家待业主补充。可用实际客户设备或明确标注节点的监测工具，无法测到的地区记为未验证。记录 DNS 结果、TLS、首页和详情状态、资源失败、TTFB 和加载体验；速度结论需注明设备、网络和日期。
